## §2 UI 清晰化(对照 `Inkast-UI-样板.html`)

**目标:** 不动任何功能,只把编辑器界面理清楚,达到样板里"我一眼知道下一步点哪"的清晰度。

**要做(逐条):**

**关键文件:** `src/components/video-editor/VideoEditor.tsx`(右侧面板/rail/标题区)、`SourceSelector.tsx`(源选择文案)、`src/components/launch/*` 或空状态组件、i18n 文案(`src/i18n/locales`)。

## §3 叠加图片 / 视频片段轨道(对照 `Inkast-剪辑器-完整版-Demo.html`)

**目标:** 剪辑中能往画面里插入**图片**或**视频片段**,作为上层叠加(画中画),可在预览里拖动/缩放、或用数值精调位置/大小/不透明度。

**现状(已有基建,复用优先):**
- `AnnotationRegion` 已支持 `type:"image"`(`imageContent` dataURL)→ **图片叠加已部分存在**,可作为"插入图片"的起点。
- 时间线是"单主视频 + 区域(zoom/trim/annotation/blur/speed)"结构,**没有第二条视频源**。

**要做(逐条):**
1. **数据模型**:`types.ts` 新增 `OverlayClipRegion`(或扩展 annotation):`{ id, start, end, source: 图片dataURL | 视频文件引用, x, y, width, opacity, z }`。视频片段需记录其自身 trim(用源视频哪一段)。
2. **时间线**:新增可叠多条的「叠加轨」;支持从媒体面板/按钮插入图片或片段(参考 Demo:媒体面板「插入图片/插入片段」+ 工具条「插图片/插片段」+「新建轨」)。
3. **预览合成**:`VideoPlayback.tsx` 在主视频之上渲染叠加图片/片段;叠加框可**拖动 + 右下角缩放 + 中心吸附参考线**(Demo 已实现这套交互,可照搬手感);选中叠加片段 ↔ 画面框双向高亮,右侧『画面』可调位置/缩放/不透明度。
4. **导出合成**(最重、最需 Code 把关):`src/lib/exporter/frameRenderer.ts` 导出每帧时,在主视频之上**合成叠加图片/片段**。视频叠加要解码第二视频源并按时间对齐——这是本块工作量与风险最大处,Code 评估用 mediabunny/mp4box(项目已依赖)或离屏 video element 逐帧取样。**先把"图片叠加"打通(复用 annotation image 的导出路径),再上"视频片段叠加"。**

**关键文件:** `types.ts`、`VideoEditor.tsx`、`VideoPlayback.tsx`、`videoPlayback/overlayUtils.ts`、`lib/exporter/frameRenderer.ts`、timeline 组件。

**验收:** 对照 Demo——插入图片/片段 → 预览里摆好位置大小 → **导出 MP4/GIF 里叠加层位置/大小/时间都正确**。分两个验收点:先图片叠加导出正确,再视频片段叠加导出正确。

**风险/取舍:** 视频片段叠加的导出合成是真功夫;若一时难,先交付「图片叠加 + 视频叠加仅预览」,导出视频叠加作为后续。

## §4 删废话 / 停顿 智能粗剪(对照 `Inkast-智能粗剪-Demo.html`)

**目标:** 录完进编辑器,自动识别**废话/语气词 + 停顿**并在时间线/转写里标出,可逐条删或**一键清除全部** → 时间线磁吸吸合、时长缩短。编辑效率的杀手锏。

**现状:** 无任何 ASR/转写/字幕代码(0 文件)。已有 `TrimRegion`(可裁段)可作为"删除区间"的落地载体。**利好:D15 已证明 mac 端能跑本地原生光标采集 + 把元数据写 json**,本地 ASR 同理可行、且契合"本地工具"定位。

**架构(本地、不上云):**
1. **抽音频**:从录制的音轨抽 PCM/wav(主进程 ffmpeg 或 mediabunny)。
2. **语音转文字带词级时间戳**:mac 用 **WhisperKit(CoreML,本地)** 或服务端 faster-whisper/WhisperX;输出 `[{word, startMs, endMs, confidence}]`。
3. **静音/停顿检测**:**Silero VAD**(或能量+时长阈值),得到 `pause[]`(start/end/dur)。
4. **废话/语气词**:词典匹配。英文有现成表;**中文自建可扩展词表**(嗯/呃/啊/那个/就是/然后/这个/反正…)+ 置信度阈值;处理"然后/就是"歧义(有时是连接词)。
5. **落到时间线**:把 pause + filler 区间生成"待删标记"(可用 `TrimRegion` 或新 `CutRegion`),默认全勾。
6. **一键粗剪**:ripple 删除选中区间 + 每段留小留白 + **音频交叉淡化**(避免剪得太碎/突兀);保留可逐条取消的复核面板(防误删真词)。

**分阶段(强烈建议,降低风险):**
- **Phase 1 — 删长停顿**:只用 VAD,**跟语言无关、最稳、收益最大**。先打通"检测停顿 → 时间线标记 → 一键删 + 交叉淡化"。
- **Phase 2 — 删废话**:加 ASR + 中文词表,转写面板(Descript 式:文字 + 废话蓝/停顿琥珀高亮 + 勾选,见 Demo)。
- **Phase 3 — 自动字幕**:同一次 ASR 顺带产出字幕轨(一套 ASR 解锁三件事:删废话/删停顿/字幕)。

**关键文件:** 新增 `src/lib/asr/*`(ASR + VAD 封装,可能跑在 worker/主进程)、`src/lib/cut/*`(filler/pause→区间)、转写面板组件、时间线集成、删除应用复用现有 trim/segment 删除 + 导出。

**验收:** 对照 Demo——录完进编辑器**自动**出现待删标记;头部显示「N 处废话 · M 处停顿 · 可省 X 秒」;一键清除后时间线吸合、时长缩短、音频接口听不出生硬;可撤销。

**风险:** ASR 集成最大;中文 filler 检测要调词表/阈值;"剪得自然"需留白+交叉淡化参数。先 Phase 1 拿到稳的收益。
