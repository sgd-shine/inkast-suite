## 任务 A — App 内配置 LLM 密钥（核心缺口，~1 天）

**现状**：分析/成片只读 `process.env`，App 内无配置入口，且 `friendlyError` 提示的「顶部黄条粘贴密钥」并不存在 → 对不上。

- `electron/analyze/analyzeService.ts:115` `hasKey:!!process.env.ANTHROPIC_API_KEY`
- `electron/analyze/analyzeService.ts:140-141` 无 key 直接拒
- `electron/analyze/analyzeService.ts:323` `x-api-key: process.env.ANTHROPIC_API_KEY`
- `electron/jobs/jobManager.ts:90-91` friendlyError 指向「黄条粘贴密钥保存」（功能缺失）
- `electron/jobs/registerJobHandlers.ts` 只注册 8 个 handler，**缺 `vf:saveLlmKey`**（INTEGRATION §3.1 列了）
- 全仓 `safeStorage` 零使用

**做法（推荐）**

1. 主进程新增密钥服务：用 Electron `safeStorage.encryptString/decryptString`，密文落 `app.getPath('userData')/keys.json`（存 `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY`）。
2. App 启动时解密读出 → 写入 `process.env`，落点放 `electron/main.ts:595-609`（引擎初始化、`registerJobHandlers`/`registerAnalyzeHandlers` **之前**）。这样下游零改动：`jobManager.ts:263 env:{...process.env}` spawn 引擎、`analyzeService.ts:74/:323` 都自动继承。
3. IPC：`registerJobHandlers.ts` 补 `vf:saveLlmKey(provider,key)` + `vf:keyStatus()`；analyze 侧 `engineInfo()`（`analyzeService.ts:112`）已报 `hasKey`，保存后刷新即绿。
4. preload：`electron/preload.ts` 的 `electronAPI` 加 `saveLlmKey` / `getKeyStatus` 桥接（沿用现有 `ipcRenderer.invoke` 模式）。
5. UI：建议在工作台顶栏放全局「密钥」入口 —— `src/components/workspace/Workspace.tsx:127`（`flex-1` 之后、语言切换旁）加按钮弹 Dialog，填两个 provider。成片 Tab 顶部再留没 key 时的黄条（兑现 `jobManager.ts:91` 的假设）。

**验收**：填 key → `keyStatus`/`engineInfo.hasKey` 转绿 → 重启 App 仍在 → `keys.json` 为密文、不在 git。

**步骤**
