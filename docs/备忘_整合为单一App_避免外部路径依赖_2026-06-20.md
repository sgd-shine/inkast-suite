## 负责人原话(需求)
> 这是一个隐患,以后我们需要这些功能被整合到一起,而不是分散在电脑设备里面的各处文件。假如某一个文件被修改了,它又无法使用了。我们在完成开发以后,要把所有的功能汇总成一个 App,避免像这样的引擎是通过路径指引到某一处。

## 现状:所有外部依赖都靠"路径 + 配置"(脆弱点)
| 依赖 | 现在怎么找 | 配置位置 | 文件没了/被移会怎样 |
|---|---|---|---|
| 成片引擎 video-pipeline | `resolvePipelineRoot` | env `INKAST_PIPELINE_ROOT` → `userData/engine.json` → 开发默认猜测 | 成片整条挂(本次就是) |
| 引擎 `.venv`(Python 1.9GB) | 引擎自带,跟随 pipelineRoot | 同上 | 自检/出片失败 |
| 发布看板数据 | `resolvePublishingRoot` | env `INKAST_PUBLISHING_DIR` → `userData/publishing.json` → 默认 | 看板空/报错 |
| 驾驶舱 vault | `resolveCockpitDir` | env `INKAST_COCKPIT_DIR` → 默认绝对路径 | 驾驶舱读不到 |
| LLM 密钥 | `loadKeysIntoEnv` | `userData/keys.json`(safeStorage 密文) | 缺 key 诚实提示(已较稳) |

## 与既有决策的张力
- 引擎 `.venv`:**1.9GB / arm64-only(mlx_metal)/ 不可重定位**(uv 硬路径、console-script shebang 已坏)。
- INTEGRATION.md §6 / R9 已决定:**"不要 vendor",保持外部路径 + 配置 + `video.sh smoke` doctor**;"自包含 Python 打包 = 另立项目"。
- 所以负责人的"汇总成一个 App"与"引擎不 vendor"直接冲突 —— 是 P6 退役阶段要正面解决的真问题。

## 落地建议(两层)
1. **近期 · 低成本(开发完成前可顺手做)**:把上面这些**散落配置全收进一个「设置」面板**(像现有 🔑 密钥弹窗),在 UI 里设引擎路径 / 发布目录 / 驾驶舱目录 / 分析模型 / 成片供应商,**不用手改磁盘文件**。底层 setter 多已存在:`saveEngineRoot`、`savePublishingRoot`、`keys:save`、`vf:setSlidesProvider`;缺的补上即可。这样"文件被改就坏"的脆弱性大降(UI 可见、可重设、有校验/doctor)。
2. **终极 · P6 大工程**:引擎自包含可重定位打包(把 video-pipeline + 一个可重定位的 Python 运行时塞进 `.app`,或换 PyInstaller/uv 可移植方案),彻底去掉外部路径依赖。**这是独立项目级工作量**,需负责人单独排期。
