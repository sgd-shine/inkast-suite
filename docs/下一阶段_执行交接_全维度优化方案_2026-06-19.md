## 0. 执行原则（先读 · 最重要）

**顺序铁律：架构 → 数据 → UI。先让功能完整可用，再考虑视觉。**
- **W1 架构**：先搭数据通道 / IPC / 服务 / 状态模型 —— 逻辑能跑通（哪怕界面还粗）。
- **W2 数据**：把真实数据接进来、回填、映射 —— 每个功能都有真数据流。
- **W3 UI**：最后做布局 / 预览 / 风格统一 / 视觉密度。

**不许假东西铁律（本阶段硬性，验收一票否决）：**
- **无假数据**：UI 上每个数字 / 卡片 / 状态都必须来自真实源（vault / 选题池 / 文件系统 / 引擎产物），禁止 mock、写死、占位假值。
- **无假接口**：每个 IPC handler 必须真实现；读不到就如实报错或显示空态，**不许编造返回桩**。
- **无假按钮**：每个按钮必须连真功能；**做不到的功能就先别放按钮**（宁缺毋假）。反面教材＝旧原型里 promote 只弹 toast。
- 叠加原有铁律：不改原件 · 无后端不上 UI · 引擎外部路径 · 反假进度 · vault 只读（Codex 仍唯一写）· 每步 tsc+test+lint 绿再提交。

## 6. 维度五 · 数据获取

### 6.1 真实性排查结论（已实测，无需改）
四 Tab 全真、**无占位桩**：驾驶舱读 vault 今日真数据（2026-06-19，6 选题/22 雷达/12 热点）· 分析真 ffmpeg+Claude · 成片真引擎+stageParser 反假进度+诚实中断态 · 资料库真路径+白名单。要修的不是造假，是下面的接线。

### 6.2 本地选题池（W1 · 数据模型核心）
- 主进程可读写 JSON（如 `userData/cockpit-pool.json`）+ IPC（读/写/改状态）。
- vault 仍只读，选题池是**叠加增量层**：展示＝vault 当日卡 ∪ 选题池（用户改的状态 / 拉片喂入 / 成片回填）。
- merge：以 `card.id` 对齐；池只存增量（status 覆盖、来源、关联产物路径），vault 刷新不丢本地状态。
- **硬理由**：流转/回填要被主进程（JobManager/AnalyzeService）读写，localStorage（渲染私有）做不到。

### 6.3 各数据源接线状态
- vault（驾驶舱）：只读，真实新鲜，连续 6 天。`electron/cockpit/cockpit.ts`，勿改只读性质。
- Publishing 文件系统（发布看板）：只读 + 映射表/容错（§5.5）。
- 引擎产物（成片/拉片，资料库）：`pipelineRoot/output`，外部路径只读+白名单。
- 引擎/Claude（成片/分析真跑）：依赖**密钥配置**（见真端到端交接）—— 没 key 就如实禁用并提示，**不许放假按钮**。
