## 2. 下一阶段方向(待讨论排序)

### A.【重点·遗留】驾驶舱界面优化
- 现状:**机制已对齐原型**(偏好引擎/选题流转/种子/富卡片),但**UI 布局与视觉保真度**可能仍需贴近 `10_知识星球/KnowledgePlanet/Operations/Publishing/Review/内容驾驶舱_原型.html`(原型是 3 栏/信息密度更高/卡片更精)或负责人的新界面要求。
- **待负责人在讨论里给出具体界面需求**(布局/密度/交互/视觉)。
- 连带要定的数据问题:
  - **选题流转写回哪里?** 现为 localStorage(因 Inkast 只读 vault)。要不要写回 vault / 建本地选题池?
  - **拉片↔驾驶舱 互喂**:拉片报告 → 驾驶舱选题素材,怎么落?(Inkast 只读 vault → 需本地"选题池"或约定写回路径)
  - 偏好面板默认/交互是否还要调。

### B. 真·端到端验收(需你的环境)
配 `ANTHROPIC_API_KEY`/`DEEPSEEK_API_KEY` + 引擎 `video-pipeline/.venv` 就绪 → 成片投想法跑出 MP4、分析拖视频出拉片报告。验收"录→拆→成"闭环。

### C. ASR 统一(钉子②)
FunASR/SenseVoice 替"批量转写"(低风险);**字级时间戳 go/no-go**(需真实中文录音,±50–80ms 门)决定是否上 Paraformer/对齐。保留 Inkast 现有词级 whisper 给交互式剪辑。详见 INTEGRATION §6。

### D. 分析(拉片)升级
单次 vision → 拉片 skill 的"逐帧细看"agentic 精修循环;接逐字稿转写(配合 C);报告 Markdown 渲染;缓存/成本优化(现 ~$25/30min)。

### E. 成片增强
Gate B(成片确认/预览,现仅 Gate A)落地;录屏导出→成片 全自动 `fs.watch` 建草稿 vs 现"预填待点";翻页 plan 编辑器完善。

### F. 资料库增强
搜索/筛选/预览/删除归档;跨类型关联(录屏↔成片↔拉片报告)。

### G. 工程 / 接管 / 收口
打包节奏(改完重打 `Inkast Suite.app`);语言默认中文;P5 接管为正式 Inkast;P7 退役清理(归档散件、确认能力已吸收,先归档再删,负责人点头才执行)。
